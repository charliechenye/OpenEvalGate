# OpenEvalGate 0.1.1 — Promptfoo evidence review and practitioner workflow

`0.1.1` is a release candidate continuing Core Compatibility v1. It connects
a pinned Promptfoo export to local Agent release review and adds practitioner
guidance and decision-card improvements. Package publication is through GitHub
Release assets; there is no PyPI publication in this plan.

## Added

- an experimental offline producer for **Promptfoo 0.123.1** with explicit
  identities, case-authoritative routes, original observations, and V1 digests;
- a synthetic demo using the same passing evals with complete controls or
  explicit `missing_rollback` / `missing_monitoring` blockers;
- a [Promptfoo tutorial](../integrations/promptfoo.md) and consumer Actions
  workflow with pinned installation, saved diagnostics, and failure propagation;
- a consistent [installation path](../installation.md), GitHub metadata draft,
  and [independent adoption protocol](../development/adoption-validation.md);
- a decision-card review checklist covering scope alignment, ownership,
  rollback, escalation, and re-review;
- a product-manager recipe for reviewing a bounded controlled launch;
- an incident-to-regression recipe and expanded incident-intake guidance;
- an agent-change review recipe connecting planned changes to affected slices,
  investigation categories, and bounded follow-up decisions;
- a Golden Eval Set Playbook workflow for stakeholder alignment, risk slices,
  evidence sources, grading, slice-based gates, ownership, and production
  learning.

## Compatibility

This release remains within Core Compatibility v1. It does not change V1
schemas, JSON output, blocker identifiers, scoring, recommendation semantics,
CLI options, or exit behavior. Decision cards and playbooks are deterministic
within the release but are not machine-readable compatibility surfaces.

## Limitations

Playbooks and templates remain experimental practitioner guidance. A report or
decision card is evidence for an organizational decision, not organizational
approval, deployment authorization, compliance certification, or a safety
guarantee. Complete provenance authorization classification and enriched
workflow or handoff validation remain deferred.
Freshness and expiry classifications do not yet consistently block a passing
recommendation. Teams must verify evidence age and current release alignment.
The Promptfoo producer is a repository example, not an official vendor
integration, and supports only the documented `0.123.1` JSON/observation format.
Synthetic runs do not establish external adoption or production performance.

## Release handoff

No new V1 schema, blocker ID, scoring, or exit semantics are introduced here.

After committing/merging the reviewed change and tag CI passing, check out the
exact `v0.1.1` commit in a clean tree. Build and verify both distributions, run
the clean-wheel smoke and four canonical byte comparisons from CI, then:

```bash
python -m build
python scripts/verify_distribution_artifacts.py --dist-dir dist
(cd dist && sha256sum *.whl *.tar.gz > SHA256SUMS)
# macOS checksum equivalent: (cd dist && shasum -a 256 *.whl *.tar.gz > SHA256SUMS)
```

Attach `openevalgate-0.1.1-py3-none-any.whl`, `openevalgate-0.1.1.tar.gz`, and
`SHA256SUMS` to the GitHub Release using this text. Both distributions must come
from the same clean tag commit. Local builds from uncommitted changes are
review candidates and must not be represented as exact-tag artifacts.
Update the workflow's pinned SHA only to a published commit containing the
producer/helper. Commit, push, tag, and Release publication require the
maintainer's explicit authorization under `AGENTS.md`; they are not performed
by preparing this release text. Do not publish to PyPI.
